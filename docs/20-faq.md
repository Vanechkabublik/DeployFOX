# Частые вопросы

**Нужны Kubernetes, Swarm или Runner?** Нет. Compose запускает панель, worker, PostgreSQL, Redis и Caddy на одном VPS; отдельный agent работает с Docker Engine.

**Можно ли открыть хостинг для клиентов?** Нет. Модель доверия — один владелец и доверенный код. Агент обладает высокими привилегиями на хосте.

**Почему mock показал SUCCESS, но сайта нет?** Mock тестирует жизненный цикл без Docker-приложений. В интерфейсе он подписан LOCAL / MOCK. Production запрещает mock на уровне конфигурации.

**Нужен GitHub токен пользователя?** Нет. App ID, installation и PEM позволяют получить короткоживущий installation token. Долговременный PEM хранится как Docker secret.

**Почему поддерживается только GitHub HTTPS URL?** Это осознанное ограничение импорта для снижения SSRF/локального доступа. Произвольные Git URL и SSH-ключи пока не поддерживаются.

**Есть ли zero-downtime?** Такой гарантии нет. Есть кандидат, HTTP healthcheck и Caddy reload, затем остановка старого контейнера. Долгие запросы, WebSocket, фоновые задачи, миграции и аварии требуют отдельных проверок.

**Что делает rollback?** Запускает предыдущий успешный образ с текущими env. Не откатывает БД и не восстанавливает удалённый image.

**Можно ли удалить volume?** Панель этого автоматически не делает. Команда down без -v сохраняет данные. Удаление volumes выполняйте только отдельно после проверенной копии и точного определения владельца.

**Где пароль базы?** Базы данных → connection. Скопируйте в переменную приложения. Это секрет; не отправляйте в чат или public repository.

**Как восстановить забытый пароль панели?** Email-reset пока нет. Сохраните менеджер паролей и SSH-доступ. Не удаляйте administrators для повторной публичной инициализации. Для административного восстановления требуется контролируемая офлайн-процедура с backup; готовой CLI reset-команды в этой версии нет.

**Можно запустить бота без порта?** Да: выберите «Фоновый процесс» без домена. Проверяются пять секунд работы процесса без рестарта. Предыдущая версия останавливается перед запуском новой; при неудаче восстанавливается. См. главу 09.

**Можно ли сменить версию PostgreSQL одним кликом?** Нет. Major upgrade требует совместимого dump/restore или штатного инструмента СУБД. Нельзя просто менять image и ожидать совместимости старого каталога.

**Куда сообщать об ошибке?** Зафиксируйте версию исходников, шаги, статус контейнеров и обезличенный фрагмент ошибки. Публичного issue tracker проекта пока нет; используйте канал, через который вы получили исходники. Не отправляйте .env, токены, PEM и dump.
