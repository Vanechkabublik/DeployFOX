# Начните здесь

DeployFox — панель для ваших собственных доверенных приложений на одном сервере. Это ранняя версия: перед установкой прочитайте [реальное состояние функций](verification.md). Не используйте её как публичный хостинг для чужого кода. Docker и BuildKit не гарантируют безопасность недоверенного кода.

## Если вы впервые работаете с сервером

1. Прочитайте [что купить](01-buying-vps.md).
2. [Подключитесь через PowerShell](02-first-ssh-connection.md).
3. [Защитите вход](03-server-security.md), сохраняя первое соединение открытым.
4. [Установите Docker](04-install-docker.md).
5. [Перенесите DeployFox и запустите установку](05-install-deployfox.md).
6. [Настройте домен](06-connect-domain.md).
7. [Создайте GitHub App](07-connect-github.md).
8. [Разверните первое приложение](08-deploy-first-project.md).
9. [Сделайте резервную копию](15-backups.md) и проверьте восстановление на отдельном сервере.

Не вводите все команды подряд вслепую. Кодовые блоки с подписью «PowerShell» выполняются на вашем компьютере. Блоки «Ubuntu» — в окне, где вы подключились по SSH. Символы `IP_СЕРВЕРА`, `ВАШ_ДОМЕН` и `ИМЯ_ФАЙЛА` обозначают ваши значения; замените их перед запуском. `example.com` и `203.0.113.10` — учебные примеры, они не ведут на ваш VPS.

## Проверить локально на Windows

1. Запустите Docker Desktop и дождитесь надписи Engine running.
2. Откройте PowerShell в папке `C:\Users\Иван\Desktop\gl\deployfox`.
3. Выполните:

```powershell
docker compose -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.local.yml ps
```

4. Дождитесь healthy у API и frontend. Откройте `http://localhost:3000`.
5. Получите только токен установки (не отправляйте его другим людям):

```powershell
docker compose -f docker-compose.local.yml exec api sh -c 'sed -n "s/^SETUP_TOKEN=//p" /run/deployfox/env'
```

6. Создайте администратора: токен, email, пароль от 12 символов. Этот пароль не связан с паролем VPS.
7. Создайте Docker image проект `nginx:alpine`, порт `80`, нажмите Deploy. В mock-режиме проходит только имитация процесса. Открываемого nginx-контейнера не будет; панель это явно показывает.

Локальная PostgreSQL использует trust только в закрытой Docker-сети без публикации портов. Не используйте этот Compose на публичном сервере. Production-конфигурация требует случайные пароли и запрещает mock-провайдер.

Остановка без потери данных:

```powershell
docker compose -f docker-compose.local.yml down
```

Не добавляйте `-v`: этот флаг удаляет volumes с базой и ключом шифрования.
