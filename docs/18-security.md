# Модель безопасности

Первая версия предназначена для одного владельца и его доверенных репозиториев. Нет публичной регистрации, пользователей клиентов или исполнения чужого кода. Владелец панели фактически управляет сервером.

API и frontend не монтируют Docker socket. Только отдельный agent получает `/var/run/docker.sock`. У агента ограниченный набор команд приложения, параметры проверяются, нет произвольных host mounts из проекта. Однако доступ к Docker API фактически даёт высокие привилегии на хосте: этот агент не является настоящей границей безопасности от атакующего администратора/скомпрометированного ядра. Docker Engine и BuildKit не являются абсолютной песочницей.

Пользовательские приложения не privileged, без socket, с cap-drop ALL, no-new-privileges, pids/CPU/RAM limits. BuildKit имеет отдельные лимиты, одну сборку обслуживает глобальная PostgreSQL-блокировка. Управляющая база находится в отдельной сети. Приложения и управляемые базы разделяют apps-сеть; это не строгая изоляция проектов друг от друга. Для первого single-owner сценария такая модель допустима, для публичного хостинга — нет.

Импорт Git ограничен github.com по HTTPS; file://, произвольный SSH, internal IP и redirects не принимаются. Agent проверяет публичный DNS и границы build paths включая symlink. DNS-проверка не равна полной защите от DNS rebinding; исходящие подключения build/application остаются возможными. Не запускайте недоверенный Dockerfile.

Пароли Argon2id; сессии — случайные токены, в БД только SHA-256. Cookies HttpOnly, SameSite=Strict и Secure в production. Изменяющие запросы требуют CSRF и совпадения Origin. Лимиты запросов через Redis, вход 5 попыток за минуту на адрес прокси. Это глобальный для установки лимит, так как браузер приходит через Next proxy. Отдельной адаптивной блокировки по источнику пока нет. Доступна TOTP 2FA с защитой от повторного кода и восемью одноразовыми резервными кодами. Настройте её в Настройки и сохраните recovery codes вне VPS. Там же можно увидеть и отозвать активные сессии.

Секреты AES-GCM с отдельным ключом. Запрещён общий доступ к .env, backup и PEM. Пароли баз возвращаются только по явной команде connection. Не делитесь журналами без проверки. Защитите доступ SSH и аккаунт GitHub своей двухфакторной аутентификацией, ограничьте App выбранными репозиториями.

Production-конфигурация не проходит внешний security audit; не называйте её production-ready. Проверьте обновления зависимостей, настройте offsite backups, мониторинг диска и восстановление прежде, чем переносить важные данные.
