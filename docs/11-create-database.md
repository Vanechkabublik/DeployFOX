# PostgreSQL, Redis и MySQL

1. Откройте Базы данных в панели.
2. Введите имя. Выберите PostgreSQL 16, Redis 7 или MySQL 8.4.
3. Нажмите Создать базу.
4. На production агент создаст Docker volume и контейнер с лимитом 512 MB, 1 CPU, без опубликованного порта. Пароль генерируется криптографически и хранится в PostgreSQL панели в зашифрованном виде.
5. Перед RUNNING агент проверяет готовность: PostgreSQL через TCP pg_isready, Redis через авторизованный PING, MySQL через SELECT 1. Особенно MySQL может инициализироваться несколько десятков секунд. Перед передачей реальных данных дополнительно проверьте подключение вашего приложения.
6. Нажмите connection. Секретная строка появится только после этого явного действия; операция записывается в аудит.
7. В проекте откройте Environment Variables и добавьте DATABASE_URL=полученная_строка. Для Redis используйте REDIS_URL, если ваше приложение ожидает такое имя.
8. Выполните Deploy приложения. Простого изменения поля недостаточно: переменные применяются при создании нового контейнера.

Контейнеры находятся в `deployfox-apps`, поэтому имя `dfdb-UUID` доступно приложениям, но не вашему домашнему компьютеру. Не заменяйте его на localhost: внутри приложения localhost означает само приложение.

Кнопки start, stop, restart управляют существующим контейнером и не удаляют volume. Backup делает pg_dump для PostgreSQL, mysqldump для MySQL или RDB export Redis в `backups/managed` на VPS. Рядом записывается SHA256. Скопируйте путь из результата операции.

Для PostgreSQL/MySQL есть restore: сначала остановите приложения, записывающие в базу, укажите **имя файла** без `/backups/` и подтвердите точным именем базы. Проверяется принадлежность UUID, формат, безопасный путь и SHA256. Восстановление заменяет данные, а при ошибке может оставить частичное состояние: не включайте приложения до проверки. PostgreSQL restore проверен реальными данными; MySQL ещё требует отдельной проверки.

Redis restore через панель пока отсутствует. При локальном тестировании RDB восстановлен в отдельный Redis без AOF и проверено значение ключа; это не заменяет процедуру восстановления работающей Redis с appendonly. Смотрите ограничения в verification.md.

На сервере сначала узнайте точное имя:

```bash
sudo docker ps --filter label=deployfox.database
```

Проверка PostgreSQL (замените UUID):

```bash
sudo docker exec dfdb-UUID pg_isready -U app -d app
```

Redis требует пароль: для диагностики используйте защищённую среду с REDISCLI_AUTH, не вставляйте пароль в shell history через `-a`. Удаление/обновление версий баз через панель намеренно отсутствует: volume не удаляется автоматически.
