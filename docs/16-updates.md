# Обновление и откат DeployFox

Автоматического обновления с неизвестного URL нет. Используйте только полученную вами проверенную версию исходного кода.

1. Прочитайте изменения и ограничения новой версии.
2. Сохраните копию исходников текущей версии, .env и keys вне VPS.
3. Сделайте backup, проверьте его на отдельной базе.
4. Сохраните текущие ID образов:

```bash
sudo docker compose -f docker-compose.prod.yml images
```

5. Перенесите новые исходники, не заменяя .env, secrets и backups.
6. Проверьте конфигурацию и соберите:

```bash
sudo docker compose -f docker-compose.prod.yml config --quiet
sudo docker compose -f docker-compose.prod.yml build
sudo docker compose -f docker-compose.prod.yml up -d --wait
sudo docker compose -f docker-compose.prod.yml ps
```

7. Войдите, проверьте проект, логи и тестовый деплой. До успешной проверки не удаляйте старые образы.

Миграции goose выполняются при запуске backend. Перед несовместимым изменением схемы продумайте восстановление. Возврат старого образа не отменяет миграции. Для ранней версии проекта автоматический rollback самой панели не реализован. Верните сохранённые исходники и совместимую базу из backup по процедуре восстановления на изолированной копии, затем переносите проверенное состояние.

Rollback пользовательского приложения доступен в карточке проекта, если в истории есть другой успешный image. Образ должен ещё существовать на VPS. Он запускается с **текущими** переменными окружения. Данные/схема базы не откатываются. Старые контейнеры и образы не удаляются автоматически; следите за диском. Не запускайте `docker system prune --volumes` как способ обновления.
