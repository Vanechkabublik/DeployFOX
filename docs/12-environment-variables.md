# Переменные окружения

Переменная окружения — настройка процесса в виде имени и значения. Например PORT=3000 или DATABASE_URL=строка_подключения. Имя чувствительно к регистру.

1. Откройте проект нажатием на имя карточки.
2. Найдите Environment Variables.
3. Вставьте строки KEY=VALUE, по одной на строку. Всё после первого `=` — значение. Кавычки автоматически не удаляются: не добавляйте их, если они не являются частью значения.
4. Нажмите Сохранить переменные.
5. Для замены вставьте то же имя с новым значением. Старое зашифрованное значение будет заменено.
6. Для удаления нажмите корзину рядом с именем, затем Сохранить переменные.
7. Нажмите Deploy для применения. Rollback образа использует текущие переменные, а не историческую версию секретов.

Имена должны соответствовать `A-Z`, `a-z`, цифрам и `_`, не начинаться с цифры. Сейчас многострочные значения не поддерживаются Docker-agent. Для PEM-ключей используйте формат base64 и декодирование внутри своего приложения.

API возвращает только имена, а не расшифрованные значения. Хранение — AES-256-GCM со случайным nonce. ENCRYPTION_KEY находится в .env на VPS, отдельно от управляющей базы; локально — в отдельном volume с закрытым файлом. **Скопируйте ключ в защищённое хранилище вне сервера.** Без него нельзя восстановить секреты из dump.

Runtime secrets не передаются в Docker build arguments или в Railpack prepare. Не добавляйте их вручную в Dockerfile. Известные значения маскируются в логах worker, но приложение тоже не должно выводить секреты: преобразованный/закодированный секрет автоматическая маскировка может не распознать.

Проверка обязательных переменных остаётся обязанностью приложения: завершайтесь с понятной ошибкой при их отсутствии. Декларативного списка required variables в панели пока нет.
